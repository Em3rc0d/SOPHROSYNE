# MK0 Evidence Execution Sequence

## Principle

Run the cheapest valid falsification first; spend on legal/data/production decisions only after the product surface is sufficiently constrained. Production MK1 remains blocked throughout this sequence.

## Stage 0 — Evidence environment
Before Q03/Q04/Q05 outcomes: instantiate manifest, freeze decision regions/precedence/sample/denominators/geography/prototype digest, assign owner/reviewer, create raw+analysis destinations, verify participant/data rights and freeze statistical/instrumentation versions.

## Stage 1 — E03-A behavioral discovery
Run primary Peru/Spanish cohort first. STOP/PIVOT/INCONCLUSIVE do not authorize the old candidate to progress. CLOSED_CONDITIONAL narrows the cohort/wedge; CLOSED_PASS proceeds.

## Stage 2 — E03-B representation
Only `CLOSED_PASS` or `CLOSED_CONDITIONAL` is promotable into repeat-use/legal packet assembly. Material representation changes require new version/retest.

## Stage 3 — parallel foundations
- E03-C 14-day repeat use;
- Q04-A deterministic harness using research-permitted data;
- Q01 packet assembly against the frozen candidate interaction.

If E03-C materially changes the candidate wedge/flow, refresh Q01 packet before external review.

## Stage 4 — E03-D pricing + Q02 candidate profiles
Pricing research before Q01 may use a non-charging, disclosed fake door only. No real payment/paid pilot until the relevant Q01 commercial-activation domains and operational requirements permit it.

Enumerate candidate DataUseProfiles that match the evidence-supported surface; collect authoritative rights, semantics and cost evidence. API convenience is not provider selection evidence.

## Stage 5 — Q01 external review
Freeze exact flow/copy/prototype/pricing/portfolio-context bundle. Obtain securities/advisory review plus the Q01 non-securities applicability matrix for privacy, consumer/subscription, marketing/claims, payments/invoicing/fiscal and e-contracting where applicable. Create aggregate Q01 receipt and propagate conditions.

Material Q01-required UX changes reopen affected Q03/Q05 evidence.

## Stage 6 — Q02 production closure
Finalize exact production profiles after product/legal/pricing constraints are stable enough. Freeze rights, semantics, freshness, entitlements, cost and fallback behavior. Missing authority -> INCONCLUSIVE, not optimistic PASS.

## Stage 7 — Q04-B optional ML
Requires Q04-A PASS, rights-compatible intended features and frozen production-semantics compatibility. Valid outcomes include INCLUDE, EXCLUDE and DEFER. EXCLUDE/DEFER do not block MK1 if no runtime ML dependency remains.

## Stage 8 — Q05 durability
Requires repeat-use evidence, material Q01 constraints and Q02-compatible semantics. Component linkage uses eligible exposed repeat users. If denominator is insufficient, use a separately preregistered extension or remain INCONCLUSIVE—do not alter denominator after inspection.

## Stage 9 — unit-economics synchronization
Version and digest a synchronization artifact connecting Q02 costs, Q03 pricing evidence, verified compliance/legal recurring costs, infra workload, payment/tax assumptions and observed support burden. Structural incompatibility creates contradiction/PIVOT/STOP; TAM optimism cannot rescue it.

## Stage 10 — cross-receipt review
Instantiate contradictions for at least Q01-vs-Q03, Q01-vs-pricing/claims, Q02-vs-Q04, Q02-cost-vs-Q03-price, Q03-repeat-use-vs-Q05 and Q05-vs-Q01/Q02. P0/P1 must resolve before promotion.

## Stage 11 — promotion packet / bootstrap
Only after Q01–Q05 aggregate decisions are each CLOSED_PASS/CLOSED_CONDITIONAL: assemble packet, contradiction log, architecture-impact review and candidate bootstrap from frozen outputs only; run Build Readiness.

## Stage 12 — MK1 authorization
Approved promotion packet + approved bootstrap + passing Build Readiness authorizes production implementation for that profile only.

## Material-change rule
A material change to the tested interaction/data/legal/quant semantics after preregistration invalidates only the affected evidence scope and requires a new version. Unrelated changes outside the tested surface do not automatically invalidate the experiment.

## Global stop/pause conditions
Fatal legal/data-rights contradiction, invalid primary instrumentation, unavailable required authority, discovered point-in-time leakage, material tested-prototype change, uncertain participant/data consent/rights, or pressure to change a primary threshold after inspection pauses the affected track. Where the failure is validity rather than candidate infeasibility, final decision is INCONCLUSIVE.
